设计目标

这个接口和页面当前聚焦回答 3 个核心问题：

现在有多少客户端在线，网络层当前有多少活跃连接
线程池和任务队列是否出现拥塞
推理吞吐、任务时延和系统资源是否处于可接受范围

一、接口定位

建议保留：

GET /api/system/status

但把它设计成一个“监控聚合接口”，一次返回 5 组信息：

connection
thread_pool
task_queue
inference
system

同时新增：

POST /api/system/heartbeat

用于前端定时上报在线状态，供 `current_clients` 和 `peak_clients` 统计使用。

三、字段设计说明

1. connection：连接与在线状态

current_clients：并发连接客户端数
这里采用“心跳在线表 + 内存维护”的方式统计，表示最近 60 秒内仍在线的客户端数量。

peak_clients：并发连接峰值
表示历史在线客户端数峰值，同样基于心跳在线表统计。

current_active_connections：当前活跃连接
表示当前仍未关闭、正由 epoll 管理的 TCP 连接数，反映网络层瞬时并发压力。

peak_active_connections：活跃连接峰值
表示历史峰值 TCP 活跃连接数。

2. thread_pool：线程池状态

core_threads：核心线程数
max_threads：最大线程数
live_threads：当前线程池中实际存活线程数
busy_threads：当前忙碌线程数
idle_threads：空闲线程数
thread_utilization：线程利用率，busy_threads / live_threads
peak_live_threads：历史峰值忙碌线程数

说明：

rejected_tasks 已删除。

3. task_queue：任务排队与执行情况

waiting_tasks：排队中任务数
running_tasks：执行中任务数
completed_tasks：累计完成任务数
failed_tasks：累计失败任务数
queue_capacity：队列容量
queue_usage：队列使用率
avg_queue_wait_ms：平均排队时间
max_queue_wait_ms：最大排队时间

说明：

这两个等待时间字段已要求做真实实现，不再保留占位值。

4. inference：推理业务质量

current_fps_total：当前总推理吞吐
avg_task_duration_ms：平均任务耗时
p95_task_duration_ms：95 分位耗时
max_task_duration_ms：最大任务耗时
tasks_per_min：每分钟处理任务数
success_rate：任务成功率
result_video_generation_rate：结果视频生成成功率

说明：

current_fps_total 已要求做真实实现。

5. system：系统资源状态

cpu_usage
memory_usage
disk_usage
uptime_seconds

说明：

gpu_usage 和 gpu_memory_usage 已删除，因为当前环境未启用 GPU 推理。

四、配套心跳接口

```text
POST /api/system/heartbeat
Content-Type: application/json
```

请求体示例：

```json
{
  "username": "chenwanyao"
}
```

前端建议每 20 到 30 秒调用一次。
