# 模型轻量化与量化实验接入说明

## 1. 目标

当前版本已经确认主要瓶颈在 `ONNX前向`。  
如果想继续明显提速，最有价值的下一步是对比：

- 原始基线模型
- 更轻量的 ONNX 模型
- 更适合 CPU 的量化 ONNX 模型

本文档的目标是让你在 **不改任务主链路** 的前提下，直接使用现有后端做多模型对比实验。

## 2. 当前后端已经具备的能力

当前系统已经支持：

- 上传多个模型：`POST /api/model/upload`
- 查看模型列表：`GET /api/model/list`
- 切换激活模型：`POST /api/model/switch`
- 提交任务时显式指定 `model_id`：`POST /api/task/submit`

因此，多模型实验不需要再改数据库结构，直接复用现有模型管理链路即可。

## 3. 推荐实验顺序

建议按下面顺序做，不要一开始就直接上量化模型。

1. 基线模型
   例如当前的 `yolov8s_onnx_v2`
2. 轻量模型
   例如同系列更小模型
3. 量化模型
   例如 CPU 友好的量化 ONNX

这样最容易形成一套完整的对比结论：

- 模型越轻，前向耗时是否明显下降
- 总处理时长下降多少
- 检测框数量或实际效果是否还能接受

## 4. 建议保持不变的实验条件

为了让结果可比，建议每次只换模型，其他条件保持一致：

- 同一个 `video_id`
- 同一个 `task_type`
- 同一个 `frame_interval`
- 同一个 `confidence_threshold`
- 同一台虚拟机
- 同一版本后端代码

## 5. 实验脚本

项目里已经新增：

- [scripts/model_benchmark.py](/home/chenwanyao/graduation_project/scripts/model_benchmark.py)

它会按你给定的 `model_id` 列表依次执行：

1. `POST /api/model/switch`
2. `POST /api/task/submit`
3. 轮询 `GET /api/task/status`
4. 从任务结果中提取关键耗时
5. 输出 Markdown 表格
6. 可选输出 CSV

## 6. 用法示例

先确认这些前提：

- 后端服务已启动
- 至少已经上传多个模型
- 你知道这些模型对应的 `model_id`
- 系统中有可用 `video_id`

示例命令：

```bash
python3 /home/chenwanyao/graduation_project/scripts/model_benchmark.py \
  --base-url http://127.0.0.1:9527 \
  --model-ids 1,2,3 \
  --video-id 1 \
  --submitted-by chenwanyao \
  --task-type vehicle_detection \
  --frame-interval 10 \
  --confidence-threshold 0.6 \
  --output-csv /home/chenwanyao/graduation_project/model_benchmark_result.csv
```

## 7. 输出结果说明

脚本会输出一张 Markdown 表，主要字段包括：

- `model_id`
- `used_model_name`
- `status`
- `processed_frame_count`
- `detection_count`
- `total_duration_ms`
- `onnx_forward_duration_ms`
- `encode_write_duration_ms`

其中最关键的是：

- `total_duration_ms`
- `onnx_forward_duration_ms`

如果更轻模型或量化模型真的有效，通常最先明显下降的是：

- `onnx_forward_duration_ms`

## 9. 论文中可直接表达的实验结论方向

你后面可以围绕下面几个问题写：

- 更轻模型是否显著降低了 CPU 前向推理时间
- 量化模型是否进一步降低了总处理时长
- 轻量化/量化是否带来了检测效果下降
- 在 VMware 虚拟化环境、CPU 推理约束下，哪种模型最适合高并发部署

## 10. 当前最推荐的实际路线

如果你现在就开始做实验，我建议：

1. 先准备 1 个基线模型
2. 再准备 1 个更轻模型
3. 最后再准备 1 个量化模型
4. 用同一条视频跑三轮
5. 直接比较 `ONNX前向` 和 `总耗时`

这样最容易尽快得到第一组有价值的数据。
