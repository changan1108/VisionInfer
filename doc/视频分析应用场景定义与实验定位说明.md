# 视频分析应用场景定义与实验定位说明

## 1. 文档目的

本文档用于明确当前毕设后端系统的核心视频分析应用场景，为后续以下工作提供统一依据：

- 模型选型
- 轻量化模型实验
- 量化模型实验
- 压测视频选择
- 论文中的实验设计与结果分析

当前系统虽然已经支持多种任务类型，但如果应用场景不先收敛，后续模型优化和量化实验会缺少明确目标，实验结论也会比较分散。因此，本阶段先对“系统主要服务于什么样的视频分析任务”做出统一定义。

## 2. 当前系统能力概述

结合现有代码实现与接口设计，系统当前已经具备以下能力：

- 接收视频分析任务请求
- 基于抽帧策略处理长视频
- 使用 YOLO 系列 ONNX 模型进行目标检测
- 输出带检测框的结果视频
- 支持高并发请求接入、任务排队与异步处理

从实现方式来看，当前系统更适合处理：

- 基于目标检测的结构化视频分析任务
- 检测对象相对明确、可用边界框表达的任务
- 对处理吞吐和系统稳定性有较高要求的任务

当前系统不太适合作为主研究对象的方向包括：

- 强依赖复杂行为理解的场景
- 强依赖时序动作识别的场景
- 强依赖多阶段识别与跨帧关联推理的场景

因此，后续应用场景应尽量选择“目标检测型视频分析”，而不是“高层行为语义理解型视频分析”。

## 3. 应用场景收敛原则

为了保证后续实验可落地、可解释、可复现，本毕设的视频分析应用场景收敛遵循以下原则：

1. 与当前系统架构匹配  
   场景应适合“抽帧 + YOLO 检测 + 结果视频回写”的处理链。

2. 与当前模型能力匹配  
   场景应主要依赖目标检测，而不是复杂时序识别。

3. 便于开展性能优化实验  
   场景应能稳定复现，并可用于比较不同模型在 CPU 环境下的推理开销。

4. 具备实际应用意义  
   场景应来自安防监控、园区治理、校园管理、交通管理等典型视频监控业务。

5. 便于后续量化实验  
   场景应能比较容易收集同分布的视频片段作为校准数据。

## 4. 推荐的应用场景定位

综合系统现状、模型特点和后续实验可行性，建议将本系统定位为：

**面向园区/校园监控视频的目标检测型视频分析系统**

进一步细化后，建议采用：

- 主应用场景：`vehicle_detection`
- 辅助应用场景：`knife_detection`

不建议把 `violation_detection` 作为主场景。

## 5. 主应用场景定义：园区/校园车辆目标检测

### 5.1 场景名称

园区/校园监控视频中的车辆目标检测与结果回放分析

### 5.2 场景描述

在园区、校园、厂区、生活区等固定监控视频场景中，系统接收用户上传的视频或已有视频资源，对视频中的车辆目标进行自动检测，并输出带有检测框标注的结果视频，用于后续的人工复核、事件排查和目标统计分析。

### 5.3 典型视频来源

- 园区道路监控
- 校园出入口监控
- 地下车库监控
- 生活区道路监控
- 停车场巡检视频

### 5.4 主要检测目标

- 小汽车
- 面包车
- 公交车
- 卡车
- 摩托车
- 自行车

### 5.5 选择该场景作为主场景的原因

1. 与 YOLO 目标检测范式高度匹配  
   车辆目标边界清晰、检测目标明确，非常适合现有 YOLO 检测链路。

2. 更适合当前系统的抽帧处理方式  
   车辆目标通常跨多帧持续出现，不需要逐帧极高精度的细粒度动作识别。

3. 便于性能实验统一控制变量  
   车辆检测视频更容易找到分辨率、视角、场景稳定的视频素材，适合做模型对比实验。

4. 更适合 CPU 推理优化研究  
   本毕设后续重点在“高并发稳定接入 + CPU 推理性能优化”，车辆检测非常适合作为主实验对象。

5. 更便于后续量化校准  
   车辆场景数据较容易采集到相似分布样本，适合构建 INT8 static quantization 所需的校准集。

### 5.6 该场景下的系统目标

在保证结果视频可生成、检测目标基本可识别的前提下，重点优化：

- 单任务处理时延
- CPU 前向推理耗时
- 并发任务下的系统稳定性
- 任务排队与资源治理能力

## 6. 辅助应用场景定义：安防视频中的刀具目标检测

### 6.1 场景名称

安防监控视频中的疑似刀具目标检测与结果回放分析

### 6.2 场景描述

系统对安防监控视频中的疑似刀具目标进行检测，并输出带标注结果视频，辅助进行安全风险排查与事件回看。

### 6.3 典型视频来源

- 楼道监控
- 宿舍区公共区域监控
- 教学楼出入口监控
- 室内公共区域监控

### 6.4 选择其作为辅助场景的原因

1. 具有较强安防应用意义  
   可体现系统具备安防类目标检测扩展能力。

2. 与主场景形成补充  
   车辆检测偏大目标、户外；刀具检测偏小目标、安防类，能够体现系统的通用性。

3. 适合作为扩展验证场景  
   可以用于证明优化后的系统不仅适用于车辆类视频，也可适配其他目标检测任务。

### 6.5 不建议作为主场景的原因

1. 小目标检测难度更高  
   刀具目标往往尺寸小、遮挡多、视角复杂，实验波动更大。

2. 更容易受到数据集质量影响  
   若数据样本分布不足，量化实验可能难以得到稳定结论。

3. 不利于先建立一套稳健的性能优化主线  
   作为辅助场景更合适，便于在论文中体现“系统可扩展性”。

## 7. 为什么不建议将 violation_detection 作为主场景

当前系统虽保留了 `violation_detection` 任务类型，但从研究和实验角度看，不建议把它作为主场景，原因如下：

1. “违规行为”语义边界不够清晰  
   它不是一个单一目标类别，而更像一个高层业务语义集合。

2. 现有 YOLO 检测链不天然擅长复杂行为理解  
   如果没有时序建模、姿态信息或事件规则，“违规行为检测”容易变得定义模糊。

3. 不利于量化实验收敛  
   由于场景边界模糊，校准数据和评价标准也不容易统一。

因此，`violation_detection` 更适合作为系统保留接口能力，而不是后续模型优化与量化实验的主研究对象。

## 8. 对后续模型实验的直接指导意义

在当前应用场景定义下，后续模型实验的重点应为：

- 主实验对象：车辆检测视频
- 辅助验证对象：刀具检测视频
- 模型对比重点：CPU 推理耗时与整体处理耗时

推荐模型实验顺序：

1. 基线模型：当前 `yolov8s_onnx_v2`
2. 轻量模型：同系列更小模型，如 `yolov8n`
3. 量化模型：适合 CPU 的 `INT8 static quantized ONNX`

在主场景下重点比较：

- `总耗时`
- `抽帧推理耗时`
- `ONNX前向耗时`
- `检测框数量`
- 结果视频可用性

## 9. 对量化实验的直接指导意义

应用场景明确后，量化实验的校准数据选择原则也就更清楚了。

对于主场景“车辆目标检测”，校准数据建议主要来自：

- 固定监控视角视频帧
- 白天/夜间各类道路画面
- 车辆远近尺度不同的画面
- 背景复杂度适中的园区/校园道路场景

量化时建议优先考虑：

- `YOLOv8n INT8 static quantized ONNX`
- `YOLOv8s INT8 static quantized ONNX`

因为 ONNX Runtime 官方更推荐 CNN 模型优先采用 static quantization，这与 YOLO 类检测模型较匹配。

## 10. 论文中的建议表述

后续在论文中，建议将系统场景描述为：

“本系统面向园区/校园监控视频分析场景，重点研究基于目标检测的视频分析任务在高并发后端中的稳定处理与性能优化问题。综合系统架构、模型形式和实验可行性，本文选取车辆目标检测作为主应用场景，并以刀具目标检测作为辅助扩展场景，在 CPU 推理约束下对多模型、轻量化模型和量化模型进行对比实验。”

## 11. 最终结论

本毕设后续视频分析应用场景建议正式收敛为：

- 主场景：园区/校园监控视频中的车辆目标检测
- 辅助场景：安防监控视频中的刀具目标检测

在此基础上，后续轻量化与量化实验应优先围绕主场景展开，这样最有利于：

- 得到稳定可复现的实验结果
- 形成清晰的性能优化主线
- 为论文提供更扎实的实验支撑
