# 前端对接--权限管理+删除接口

本文档用于指导前端适配 VisionInfer V4.0 新增的权限管理、软删除、任务取消能力。

## 1. V4.0 前端需要关注的变化

### 1.1 新增权限字段

后端数据库新增：

| 字段 | 含义 | 取值 |
|---|---|---|
| `users.permission_level` | 系统权限等级 | `0=operator`，`1=admin` |
| `users.account_status` | 账号状态 | `active`，`disabled` |

注意：

- `users.role` 仍然只是用户自己填写的职位/职能，例如“算法工程师”“运维人员”，不能当作权限字段使用。
- 普通注册接口默认创建 `operator`，即 `permission_level=0`。
- `admin` 不通过普通注册创建，一般由数据库初始化或已有管理员授权创建。
- 登录接口和用户信息接口都会返回 `permission_level`、`account_status`，前端可以基于这两个字段做菜单、按钮和页面权限控制。

### 1.2 新增接口汇总

| 模块 | 方法 | 接口 | 作用 |
|---|---|---|---|
| 模型模块 | `DELETE` | `/api/model?id=模型ID` | 软删除模型 |
| 视频模块 | `DELETE` | `/api/video?id=视频ID` | 软删除视频 |
| 任务模块 | `DELETE` | `/api/task?id=任务ID` | 软删除任务记录 |
| 任务模块 | `POST` | `/api/task/cancel` | 取消任务 |
| 用户模块 | `GET` | `/api/user/list` | 管理员查询用户列表 |
| 用户模块 | `DELETE` | `/api/user?username=用户名` | 禁用用户账号 |

所有删除都是软删除：

- 后端只更新 `is_deleted/deleted_at/deleted_by` 或 `account_status`。
- 已删除数据不会再出现在列表、详情、统计接口中。
- 模型文件、视频文件、结果文件当前不会物理删除。

## 2. 操作者身份传递规则

### 2.1 DELETE 接口

`DELETE` 接口统一通过请求头传操作者用户名：

```http
X-Operator-Username: 当前登录用户名
```

前端调用以下接口时都要带这个 Header：

```text
DELETE /api/model?id=模型ID
DELETE /api/video?id=视频ID
DELETE /api/task?id=任务ID
DELETE /api/user?username=用户名
```

### 2.2 取消任务接口

`POST /api/task/cancel` 不使用 `X-Operator-Username`，操作者放在 JSON Body 中：

```json
{
  "operator_username": "chenwanyao",
  "task_id": 12
}
```

这样和当前项目里其他 `POST` 请求的风格保持一致。

## 3. 前端权限展示建议

### 3.1 两种权限

| 权限 | permission_level | 前端含义 |
|---|---:|---|
| 普通操作员 | `0` | 只能操作自己上传/提交的资源 |
| 管理员 | `1` | 可以操作全局资源，并可以禁用用户 |

### 3.2 前端不要使用 role 判断权限

错误做法：

```js
if (user.role === 'admin') {
  showAdminButton()
}
```

原因：`role` 是用户自定义职位字段，不是权限字段。

推荐做法：

- 使用 `permission_level === 1` 判断管理员。
- 使用 `permission_level === 0` 判断普通操作员。
- 使用 `account_status === 'disabled'` 判断账号已被禁用。
- 前端展示权限按钮时可以先根据本地用户信息控制显隐，但最终仍以后端 `401/403` 返回为准。

## 4. 用户模块对接

### 4.1 相关接口

```text
POST   /api/user/add
POST   /api/user/login
GET    /api/user/info?username=用户名
GET    /api/user/list
POST   /api/user/update
POST   /api/user/change-password
DELETE /api/user?username=用户名
```

### 4.2 权限规则

| 操作 | operator | admin |
|---|---|---|
| 注册用户 | 可以 | 可以 |
| 登录 | 可以 | 可以 |
| 查看/修改个人信息 | 可以 | 可以 |
| 修改自己的密码 | 可以 | 可以 |
| 查看用户列表 | 不可以 | 可以 |
| 禁用用户 | 不可以 | 可以 |
| 禁用自己 | 不可以 | 不可以 |

### 4.3 登录接口返回

请求：

```http
POST /api/user/login
Content-Type: application/json
```

```json
{
  "username": "chenwanyao",
  "password": "123456"
}
```

成功响应：

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "id": 1,
    "username": "chenwanyao",
    "role": "算法工程师",
    "permission_level": 1,
    "account_status": "active"
  }
}
```

前端适配建议：

- 登录成功后保存 `username`，用于后续权限接口传操作者身份。
- 保存 `permission_level`，用于判断是否展示管理员菜单和跨用户删除能力。
- 保存 `account_status`，如果不是 `active`，前端应阻止进入系统；正常情况下禁用用户登录会直接失败。
- 不要用 `role` 判断权限。

### 4.4 用户详情接口返回

请求：

```http
GET /api/user/info?username=chenwanyao
```

成功响应中的 `data` 会包含：

```json
{
  "code": 200,
  "msg": "获取用户信息成功",
  "data": {
    "username": "chenwanyao",
    "nickname": "陈婉瑶",
    "employee_id": "001",
    "email": "test@example.com",
    "phone": "13800138000",
    "department": "研发中心",
    "location": "Beijing",
    "timezone": "Asia/Shanghai",
    "role": "算法工程师",
    "permission_level": 1,
    "account_status": "active",
    "bio": "",
    "last_login": "2026-05-31 10:20:00"
  }
}
```

前端适配建议：

- 个人中心、用户信息缓存、权限菜单刷新时可以调用该接口。
- 如果用户权限在后台被调整，前端重新请求该接口即可拿到最新 `permission_level`。
- 如果用户被禁用，`account_status` 会变为 `disabled`。

### 4.5 修改密码接口

请求：

```http
POST /api/user/change-password
Content-Type: application/json
```

```json
{
  "username": "cwy1",
  "old_password": "旧密码",
  "new_password": "新密码"
}
```

成功响应：

```json
{
  "code": 200,
  "msg": "密码修改成功"
}
```

常见失败：

| 场景 | 状态码 | msg |
|---|---:|---|
| 原密码错误 | 400 | 原密码错误 |
| 新密码少于 6 位 | 400 | 新密码长度不能少于6位 |
| 账号不存在或已禁用 | 403 | 账号不存在或已被禁用 |
| 缺少必填字段 | 400 | username、old_password、new_password 为必填项 |

前端适配建议：

- 个人中心或账号安全页面增加“修改密码”表单。
- 表单字段：原密码、新密码、确认新密码。
- 前端先校验新密码不少于 6 位，并校验两次新密码一致。
- 修改成功后建议提示用户重新登录。

### 4.6 用户列表接口

该接口用于前端“用户管理”页面展示表格、筛选用户、查看账号状态，并配合禁用用户接口使用。

请求：

```http
GET /api/user/list?username=cwy&employee_id=001&status=active&permission_level=0&limit=20&offset=0
X-Operator-Username: admin
```

查询参数：

| 参数 | 是否必填 | 说明 |
|---|---|---|
| `username` | 否 | 按用户名模糊搜索 |
| `employee_id` | 否 | 按工号模糊搜索 |
| `status` | 否 | `active` 或 `disabled` |
| `permission_level` | 否 | `0` 或 `1` |
| `limit` | 否 | 默认 `20`，范围 `1-100` |
| `offset` | 否 | 默认 `0` |

单独筛选示例：

```text
GET /api/user/list?username=cwy
GET /api/user/list?employee_id=001
```

权限规则：

- 只有 `permission_level=1` 的管理员可以调用。
- 普通操作员调用返回 `403`。

普通操作员失败响应：

```json
{
  "code": 403,
  "msg": "权限不足，仅管理员可查看用户列表"
}
```

成功响应：

```json
{
  "code": 200,
  "msg": "获取用户列表成功",
  "data": {
    "total": 36,
    "limit": 20,
    "offset": 0,
    "items": [
      {
        "id": 1,
        "username": "admin",
        "nickname": "系统管理员",
        "employee_id": "001",
        "email": "admin@example.com",
        "phone": "13800138000",
        "department": "AI视觉计算实验室",
        "location": "北京",
        "timezone": "Asia/Shanghai",
        "role": "系统管理员",
        "permission_level": 1,
        "account_status": "active",
        "last_login": "2026-05-31 10:20:11",
        "created_at": "2026-05-01 09:00:00",
        "updated_at": ""
      }
    ]
  }
}
```

字段说明：

- `permission_level`：必须使用该字段显示“管理员/操作员”。
- `account_status`：必须使用该字段显示“正常/已禁用”。
- `username`：禁用用户时传给 `DELETE /api/user?username=用户名`。
- `employee_id`：用于用户管理页识别人员。
- `role`：只作为职位/职能展示，不能用于权限判断。
- `last_login`：用于展示最近登录时间。
- `created_at`：当前由数据库 `create_time` 映射而来。
- `updated_at`：当前 users 表没有真实更新时间字段，V4.0 暂时返回空字符串。

前端适配建议：

- 用户管理页顶部增加筛选：用户名、工号、账号状态、权限等级。
- 表格列建议：用户名、昵称、工号、权限、账号状态、部门、最近登录、操作。
- 管理员不能禁用自己，前端可用 `row.username === currentUsername` 禁用按钮。
- `account_status === 'disabled'` 时按钮显示“已禁用”。
- `account_status === 'active'` 且不是自己时按钮显示“禁用用户”。
- 禁用成功后重新请求 `GET /api/user/list`，刷新后该用户应显示为 `disabled`。

### 4.7 禁用用户接口

请求：

```http
DELETE /api/user?username=operator1
X-Operator-Username: admin
```

成功响应：

```json
{
  "code": 200,
  "msg": "用户已禁用",
  "data": {
    "username": "operator1",
    "account_status": "disabled"
  }
}
```

前端适配建议：

- 用户管理页面增加“禁用用户”按钮。
- 该按钮只建议管理员可见；当前无法从接口拿到权限时，可以保留按钮并依赖后端 `403` 兜底。
- 点击前弹出二次确认。
- 禁用成功后刷新用户列表或把该用户状态改为 `disabled`。
- 被禁用用户再次登录会返回 `401`，提示“用户名不存在、密码错误或账号已被禁用”。

## 5. 模型模块对接

### 5.1 相关接口

```text
POST   /api/model/upload
POST   /api/model/add
POST   /api/model/switch
GET    /api/model/current
GET    /api/model/list
DELETE /api/model?id=模型ID
```

### 5.2 权限规则

| 操作 | operator | admin |
|---|---|---|
| 上传模型 | 可以 | 可以 |
| 查看模型列表 | 可以 | 可以 |
| 切换激活模型 | 当前保持原逻辑 | 当前保持原逻辑 |
| 删除自己上传的非激活模型 | 可以 | 可以 |
| 删除别人上传的模型 | 不可以 | 可以 |
| 删除当前激活模型 | 不可以 | 不可以 |

### 5.3 删除模型接口

请求：

```http
DELETE /api/model?id=3
X-Operator-Username: chenwanyao
```

成功响应：

```json
{
  "code": 200,
  "msg": "模型删除成功",
  "data": {
    "model_id": 3,
    "delete_mode": "soft_delete"
  }
}
```

常见失败：

| 场景 | 状态码 | msg |
|---|---:|---|
| 未传 `id` | 400 | 缺少模型 id 参数 |
| 模型不存在或已删除 | 404 | 模型不存在或已删除 |
| 删除别人上传的模型 | 403 | 权限不足，只能删除自己上传的模型 |
| 删除当前激活模型 | 400 | 当前激活模型不允许删除，请先切换到其他模型 |

前端适配建议：

- 模型列表每行增加“删除”操作。
- `is_active=true` 的模型删除按钮置灰，并提示“当前激活模型不能删除”。
- operator 只允许删除 `uploaded_by === 当前用户名` 的模型。
- admin 可以删除所有非激活模型。
- 删除成功后重新请求 `GET /api/model/list`，或从本地列表移除该模型。

请求：

```http
DELETE /api/video?id=5
X-Operator-Username: chenwanyao
```

成功响应：

```json
{
  "code": 200,
  "msg": "视频删除成功",
  "data": {
    "video_id": 5,
    "delete_mode": "soft_delete"
  }
}
```

常见失败：

| 场景 | 状态码 | msg |
|---|---:|---|
| 未传 `id` | 400 | 缺少视频 id 参数 |
| 视频不存在或已删除 | 404 | 视频不存在或已删除 |
| 删除别人上传的视频 | 403 | 权限不足，只能删除自己上传的视频 |
| 视频存在待处理或处理中的任务 | 400 | 视频存在待处理或处理中的任务，暂不允许删除 |

- 视频列表或视频详情页增加“删除视频”按钮。

- 视频列表接口不一定包含任务引用数量，详情接口会返回：

```json
{
  "has_task_usage": true,
  "task_usage_count": 2
}
```

- 如果前端需要准确判断普通操作员是否可删除，建议在详情页调用 `GET /api/video/info?id=视频ID` 后再决定按钮状态。
- 删除成功后重新请求 `GET /api/video/list`。

## 7. 任务模块对接

### 7.1 相关接口

```text
POST   /api/task/submit
GET    /api/task/status?id=任务ID
GET    /api/task/list
GET    /api/task/stats
POST   /api/task/cancel
DELETE /api/task?id=任务ID
```

### 7.2 任务状态

当前任务状态包括：

```text
PENDING
QUEUED
PROCESSING
COMPLETED
CANCELLED
REJECTED_QUEUE_FULL
REJECTED_DISK_FULL
FAILED_INPUT_NOT_FOUND
FAILED_OUTPUT_DIR
FAILED_METADATA
FAILED_INFERENCE
FAILED_ENCODE
FAILED_OUTPUT_COPY
FAILED_RUNTIME
```

前端可按以下规则分组展示：

| 分组 | 状态 |
|---|---|
| 等待中 | `PENDING`，`QUEUED` |
| 处理中 | `PROCESSING` |
| 成功 | `COMPLETED` |
| 已取消 | `CANCELLED` |
| 已拒绝 | `REJECTED_*` |
| 失败 | `FAILED_*` |

### 7.3 取消任务接口

请求：

```http
POST /api/task/cancel
Content-Type: application/json
```

```json
{
  "operator_username": "chenwanyao",
  "task_id": 12
}
```

状态规则：

| 状态 | 是否可删除 | 是否可取消 | 前端按钮建议 |
|---|---|---|---|
| `PENDING` | 不建议 | 可以 | 显示“取消” |
| `QUEUED` | 不建议 | 可以 | 显示“取消” |
| `PROCESSING` | 不建议 | 可以真正取消 | 显示“取消” |
| `COMPLETED` | 可以 | 不需要 | 显示“删除记录” |
| `FAILED_*` | 可以 | 不需要 | 显示“删除记录” |
| `REJECTED_*` | 可以 | 不需要 | 显示“删除记录” |
| `CANCELLED` | 可以 | 不需要 | 显示“删除记录” |

成功响应一：取消等待中的任务：

```json
{
  "code": 200,
  "msg": "任务已取消",
  "data": {
    "task_id": 12,
    "status": "CANCELLED"
  }
}
```

成功响应二：处理中的任务提交取消请求，后端处理线程会在检查点安全退出：

```json
{
  "code": 200,
  "msg": "任务取消请求已提交，处理线程将尽快停止",
  "data": {
    "task_id": 12,
    "status": "PROCESSING"
  }
}
```

前端适配建议：

- `PENDING/QUEUED`：点击取消后，成功时可以直接把状态更新为 `CANCELLED`。
- `PROCESSING`：点击后提示“取消请求已提交”，继续轮询任务状态；处理线程检测到取消标记后会把任务最终更新为 `CANCELLED`。
- `COMPLETED/FAILED_*/REJECTED_*/CANCELLED`：不展示取消按钮。
- operator 只能取消 `submitted_by === 当前用户名` 的任务。
- admin 可以取消所有人的任务。

### 7.4 删除任务记录接口

请求：

```http
DELETE /api/task?id=12
X-Operator-Username: chenwanyao
```

成功响应：

```json
{
  "code": 200,
  "msg": "任务记录删除成功",
  "data": {
    "task_id": 12,
    "delete_mode": "soft_delete"
  }
}
```

常见失败：

| 场景 | 状态码 | msg |
|---|---:|---|
| 未传 `id` | 400 | 缺少任务 id 参数 |
| 任务不存在或已删除 | 404 | 任务不存在或已删除 |
| 删除别人提交的任务 | 403 | 权限不足，只能删除自己提交的任务记录 |
| 删除未结束任务 | 400 | PENDING、QUEUED、PROCESSING 状态任务不允许直接删除，请先取消任务 |

- 删除成功后重新请求 `GET /api/task/list` 和 `GET /api/task/stats`。

## 8. 通用错误处理

新增权限接口的返回体仍然遵循：

```json
{
  "code": 403,
  "msg": "权限不足，只能删除自己上传的模型"
}
```

前端建议统一按 `code/msg` 处理：

| HTTP 状态码 | 含义 | 前端提示建议 |
|---|---|---|
| 200 | 操作成功 | Toast 成功，并刷新列表 |
| 400 | 参数错误或业务状态不允许 | 直接展示 `msg` |
| 401 | 缺少操作者、操作者不存在、登录失败 | 提示重新登录或检查当前用户 |
| 403 | 账号禁用、权限不足、权限等级非法 | 提示权限不足或账号不可用 |
| 404 | 资源不存在或已删除 | 提示资源不存在，并刷新列表 |
| 500 | 后端执行失败 | 提示系统异常 |

## 9. 前端请求封装建议

### 9.1 DELETE 请求封装

示例：

```js
async function deleteWithOperator(url, currentUsername) {
  const res = await fetch(url, {
    method: 'DELETE',
    headers: {
      'X-Operator-Username': currentUsername
    }
  })
  return await res.json()
}
```

使用：

```js
await deleteWithOperator(`${baseUrl}/api/model?id=${modelId}`, currentUsername)
await deleteWithOperator(`${baseUrl}/api/video?id=${videoId}`, currentUsername)
await deleteWithOperator(`${baseUrl}/api/task?id=${taskId}`, currentUsername)
await deleteWithOperator(`${baseUrl}/api/user?username=${targetUsername}`, currentUsername)
```

### 9.2 取消任务请求封装

示例：

```js
async function cancelTask(taskId, currentUsername) {
  const res = await fetch(`${baseUrl}/api/task/cancel`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      operator_username: currentUsername,
      task_id: taskId
    })
  })
  return await res.json()
}
```

## 10. 前端页面改造清单

### 10.1 登录/用户状态

- 登录成功后保存当前用户名、`permission_level`、`account_status`。
- 被禁用账号登录失败时展示后端 `msg`。
- 不要使用 `role` 判断管理员权限。
- 使用 `permission_level === 1` 精确控制管理员菜单、用户管理入口和跨用户操作按钮。

### 10.2 模型管理页面

- 模型列表增加“删除”按钮。
- 当前激活模型禁用删除按钮。
- 删除成功后刷新模型列表。
- 删除当前模型失败时，引导用户先切换模型。

### 10.3 视频管理页面

- 视频列表或详情页增加“删除视频”按钮。
- 删除前确认。
- 删除成功后刷新视频列表。
- 如果接口提示“存在待处理或处理中的任务”，引导用户先到任务页面取消或等待完成。

### 10.4 任务管理页面

- `PENDING/QUEUED/PROCESSING` 展示“取消”按钮。
- `COMPLETED/CANCELLED/FAILED_*/REJECTED_*` 展示“删除记录”按钮。
- 取消 `PROCESSING` 任务后继续轮询状态。
- 删除成功后刷新任务列表和统计数据。

### 10.5 用户管理页面

- 管理员页面调用 `GET /api/user/list` 展示用户表格。
- 顶部筛选支持用户名、工号、账号状态、权限等级。
- 表格展示用户名、昵称、工号、权限、账号状态、部门、最近登录。
- 管理员页面增加“禁用用户”按钮。
- 禁止禁用当前登录用户。
- 禁用成功后刷新用户数据。
- operator 调用禁用接口会返回 `403`，前端展示权限不足即可。
