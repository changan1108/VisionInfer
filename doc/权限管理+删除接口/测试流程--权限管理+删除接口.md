# VisionInfer V4.0 测试流程--权限管理+删除接口

## 1. V4.0 新增接口汇总

本版本围绕“权限管理 + 删除接口”新增了以下接口：

| 模块 | 方法 | 接口 | 功能 |
|---|---|---|---|
| 任务模块 | `DELETE` | `/api/task?id=任务ID` | 软删除任务记录 |
| 任务模块 | `POST` | `/api/task/cancel` | 取消任务 |
| 视频模块 | `DELETE` | `/api/video?id=视频ID` | 软删除已上传视频 |
| 模型模块 | `DELETE` | `/api/model?id=模型ID` | 软删除模型记录 |
| 用户模块 | `GET` | `/api/user/list` | 管理员查询用户列表 |
| 用户模块 | `POST` | `/api/user/change-password` | 修改用户密码 |
| 用户模块 | `DELETE` | `/api/user?username=用户名` | 禁用用户账号 |

同时，本版本新增了权限基础能力：

- `users.permission_level`：数字权限字段，`0=operator`，`1=admin`。
- `users.account_status`：账号状态字段，`active/disabled`。
- `AuthService`：统一读取操作者身份并判断权限。
- CORS 已支持 `DELETE` 方法，并放行 `X-Operator-Username` 请求头。

`DELETE` 接口的权限身份推荐通过请求头传递：

```http
X-Operator-Username: admin_user
```

`POST /api/task/cancel` 为了保持 POST 请求风格统一，权限身份从 JSON Body 读取：

```json
{
  "operator_username": "chenwanyao",
  "task_id": 12
}
```

## 2. 权限角色说明

系统只定义两种权限：

| permission_level | 权限名称 | 说明 |
|---|---|---|
| `0` | operator | 普通操作员，只能管理自己创建或上传的资源 |
| `1` | admin | 管理员，可以管理全局资源 |

注意：

- `users.role` 仍然是用户自定义职位，例如“算法工程师”“操作员”等，不参与权限判断。
- 被禁用用户 `account_status=disabled` 不能继续登录，也不能作为操作者调用权限接口。

## 3. 各模块权限与接口

### 3.1 用户模块

涉及接口：

```text
POST   /api/user/add
POST   /api/user/login
GET    /api/user/info?username=xxx
GET    /api/user/list
POST   /api/user/update
POST   /api/user/change-password
DELETE /api/user?username=xxx
```

权限规则：

| 操作 | admin | operator |
|---|---|---|
| 添加用户 | 可以 | 当前接口未限制 |
| 登录 | 可以 | 可以 |
| 查看用户信息 | 当前接口未限制 | 当前接口未限制 |
| 查看用户列表 | 可以 | 不允许 |
| 修改用户信息 | 当前接口未限制 | 当前接口未限制 |
| 修改密码 | 可以 | 可以 |
| 禁用用户 | 可以禁用其他用户 | 不允许 |
| 禁用自己 | 不允许 | 不允许 |

重点测试：

- admin 可以查看用户列表。
- operator 调用 `GET /api/user/list` 返回 `403`。
- 原密码正确时可以修改密码。
- 原密码错误时修改密码返回 `400`。
- admin 可以禁用 operator。
- operator 调用 `DELETE /api/user` 返回 `403`。
- admin 禁用自己返回 `400`。
- 被禁用用户再次登录失败。

### 3.2 模型模块

涉及接口：

```text
POST   /api/model/upload
POST   /api/model/add
POST   /api/model/switch
GET    /api/model/current
GET    /api/model/list
DELETE /api/model?id=模型ID
```

权限规则：

| 操作 | admin | operator |
|---|---|---|
| 上传模型 | 可以 | 可以 |
| 查询模型列表 | 可以 | 可以 |
| 查询当前模型 | 可以 | 可以 |
| 切换当前模型 | 当前接口未限制 | 当前接口未限制 |
| 删除模型 | 可以删除任意非激活模型 | 只能删除自己上传的非激活模型 |
| 删除当前激活模型 | 不允许 | 不允许 |

重点测试：

- operator 可以删除自己上传的非激活模型。
- operator 删除别人上传的模型返回 `403`。
- admin 可以删除任意非激活模型。
- 删除当前激活模型返回 `400`。
- 删除成功后，`GET /api/model/list` 不再返回该模型。

### 3.3 视频模块

涉及接口：

```text
POST   /api/video/upload
GET    /api/video/list
GET    /api/video/info?id=视频ID
GET    /api/video/preview?id=视频ID
DELETE /api/video?id=视频ID
GET    /api/video/result?task_id=任务ID
```

权限规则：

| 操作 | admin | operator |
|---|---|---|
| 上传视频 | 可以 | 可以 |
| 查询视频列表 | 可以 | 可以 |
| 查询视频详情 | 可以 | 可以 |
| 预览视频 | 可以 | 可以 |
| 删除视频 | 可以删除任意无运行中任务的视频 | 只能删除自己上传、且未被历史任务引用的视频 |
| 删除存在运行中任务的视频 | 不允许 | 不允许 |
| 删除存在历史任务引用的视频 | 可以软删除 | 不允许 |

重点测试：

- operator 可以删除自己上传且未被任务引用的视频。
- operator 删除别人上传的视频返回 `403`。
- operator 删除已有历史任务引用的视频返回 `400`。
- admin 可以软删除已有历史任务引用的视频。
- 有 `PENDING/QUEUED/PROCESSING` 任务引用的视频不能删除。
- 删除成功后，`GET /api/video/list` 不再返回该视频。

### 3.4 任务模块

涉及接口：

```text
POST   /api/task/submit
GET    /api/task/status?id=任务ID
GET    /api/task/list
GET    /api/task/stats
POST   /api/task/cancel
DELETE /api/task?id=任务ID
```

权限规则：

| 操作 | admin | operator |
|---|---|---|
| 提交任务 | 可以 | 可以 |
| 查询任务状态 | 可以 | 可以 |
| 查询任务列表 | 可以 | 可以 |
| 查询任务统计 | 可以 | 可以 |
| 取消任务 | 可以取消任意任务 | 只能取消自己提交的任务 |
| 删除任务记录 | 可以删除任意终态任务 | 只能删除自己提交的终态任务 |

任务删除状态规则：

| 状态 | 是否可删除 | 是否可取消 |
|---|---|---|
| `PENDING` | 不建议，接口会拒绝 | 可以 |
| `QUEUED` | 不建议，接口会拒绝 | 可以 |
| `PROCESSING` | 不建议，接口会拒绝 | 可以真正取消 |
| `COMPLETED` | 可以 | 不需要 |
| `FAILED_*` | 可以 | 不需要 |
| `REJECTED_*` | 可以 | 不需要 |
| `CANCELLED` | 可以 | 已取消 |

重点测试：

- operator 可以删除自己提交的终态任务。
- operator 删除别人提交的任务返回 `403`。
- 删除 `PENDING/QUEUED/PROCESSING` 任务返回 `400`。
- admin 可以删除任意终态任务。
- `POST /api/task/cancel` 可以取消 `PENDING/QUEUED` 任务。
- `POST /api/task/cancel` 可以对 `PROCESSING` 任务写入取消标记，处理线程检测到后会安全退出，并把任务最终更新为 `CANCELLED`。

## 4. Windows Apipost 简单功能测试流程

### 4.1 测试前准备

1. 确认后端服务已经启动。

默认地址示例：

```text
http://192.168.88.131:9527
```

如果在本机或虚拟机端口转发环境中测试，也可以使用：

```text
http://127.0.0.1:9527
```

2. 确认数据库已执行迁移。

需要确认 `005_add_permission_and_soft_delete.sql` 对应字段存在：

```sql
permission_level
account_status
is_deleted
deleted_at
deleted_by
cancel_requested
cancelled_at
```

3. 准备两个测试用户。

建议使用 SQL 手动设置权限：

```sql
UPDATE users SET permission_level = 1, account_status = 'active' WHERE username = 'admin';
UPDATE users SET permission_level = 0, account_status = 'active' WHERE username = 'operator1';
UPDATE users SET permission_level = 0, account_status = 'active' WHERE username = 'operator2';
```

4. Apipost 中创建环境变量。

建议创建：

| 变量名 | 示例值 |
|---|---|
| `base_url` | `http://192.168.88.131:9527` |
| `admin_user` | `admin` |
| `operator1` | `operator1` |
| `operator2` | `operator2` |

5. 删除类接口统一添加 Header。

```http
X-Operator-Username: {{admin_user}}
```

或者：

```http
X-Operator-Username: {{operator1}}
```

### 4.2 通用测试顺序

建议按下面顺序测试：

1. 用户登录与禁用测试。
2. 模型上传、切换、删除测试。
3. 视频上传、删除测试。
4. 任务提交、取消、删除测试。
5. 权限越权测试。
6. 删除后列表查询验证。

## 6. 测试通过标准

本轮功能测试通过标准如下：

- 所有新增接口能正常响应。
- `DELETE` 请求不会被 CORS 或 Router 拦截。
- operator 只能删除自己的资源。
- admin 可以删除全局资源，但不能禁用自己、不能删除当前激活模型。
- 删除任务、视频、模型后，对应列表接口不再返回该资源。
- 删除操作只做软删除，数据库记录仍存在，且 `is_deleted=1`。
- 用户被禁用后无法登录。
- `PROCESSING` 任务取消请求能写入 `cancel_requested=1`，并在处理线程检查到后变为 `CANCELLED`。

## 7. 建议测试后的数据库检查 SQL
