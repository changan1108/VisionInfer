# VisionInfer 后端接口对接文档

## 1. 基本说明

- 项目名称：`VisionInfer`
- 默认服务地址：`http://192.168.88.131:9527`
- 局域网联调示例：`http://192.168.88.131:9527`
- 数据格式：
  - 普通业务接口默认返回 `application/json`
  - 视频结果接口返回 `video/mp4`
- 当前未使用登录态 Token 机制，用户模块接口按显式参数传递

统一返回格式大多数为：

```json
{
  "code": 200,
  "msg": "ok",
  "data": {}
}
```

常见状态码：

- `200`：成功
- `400`：请求参数错误
- `401`：登录失败
- `404`：资源不存在
- `503`：系统繁忙，任务队列已满
- `507`：磁盘剩余空间不足，任务被拒绝
- `500`：服务端处理失败

## 2. 推荐联调顺序

本系统是一个统一的“视频分析系统”，内部按功能划分为：

- 用户管理模块
- 模型管理模块
- 视频分析模块
- 系统监控模块

前端建议按下面顺序联调，确保四个模块都覆盖到：

1. 用户管理模块
   先联调用户注册、登录、信息查询、信息修改，确认前端具备基础用户身份信息。
2. 模型管理模块
   联调模型新增、模型列表、当前模型查询、模型切换，确认后端有可用激活模型。
3. 视频分析模块
   联调视频上传、任务提交、任务状态查询、任务列表、任务统计、结果视频播放。
4. 系统监控模块
   联调系统状态接口，确认前端首页/总览页能展示运行状态、任务统计和模型摘要。
5. 全链路联调
   用“用户登录 -> 选择模型 -> 上传视频 -> 提交任务 -> 查看任务状态 -> 播放结果视频 -> 查看系统监控”的顺序跑通完整流程。

## 3. 用户模块

### 3.1 添加用户

- 方法：`POST`
- 路径：`/api/user/add`
- 请求头：`Content-Type: application/json`
- PS:特有规约细节：
  工号 (employee_id): 输入框限制为最多且必须是 3 位，输入时采用正则拦截只允许数字（即 000~999）。
  所属中心 (department): 固定下拉选项，只能是 AI 视觉计算实验室、大数据分析中心、边缘计算研发部 之一。
  地理位置 (location): 不需要用户手动输入，它是与 department 选项进行一对一数据绑定的，所选中心一变，地理位置自动锁定对应地点。
  时区 (timezone): 这是一个包含括号的无空格字符串数组，只能在这五个选项里选：UTC+8(Beijing)、UTC+9(Tokyo)、UTC+0(London)、UTC-5(New York)、UTC-8(Los Angeles)。
  说明: 新注册时 role（职能角色）和 bio（简介）等都由用户作为自定义字符串填写。

请求体示例：

```json
{
  "username": "chenwanyao",
  "password": "123456",
  "nickname": "陈万垚",
  "employee_id": "001",
  "email": "test@example.com",
  "phone": "13800138000",
  "department": "AI 视觉计算实验室",
  "location": "上海市 浦东新区 研发中心",
  "timezone": "UTC+8(Beijing)",
  "bio": "test user",
  "role": "操作员"
}
```

成功响应示例：

```json
{
  "code": 200,
  "msg": "添加用户成功"
}
```

任务提交失败时，当前版本还可能返回：

- `503`：系统繁忙，通常对应 `REJECTED_QUEUE_FULL`
- `507`：磁盘空间不足，通常对应 `REJECTED_DISK_FULL`

前端建议：

- `503` 提示“系统繁忙，请稍后重试”
- `507` 提示“磁盘空间不足，请联系管理员或稍后重试”

### 4.2 提交分析任务

- 方法：`POST`
- 路径：`/api/task/submit`
- 请求头：`Content-Type: application/json`

请求体示例：

```json
{
  "task_name": "宿舍楼夜间刀具巡检",
  "task_type": "knife_detection",
  "submitted_by": "chenwanyao",
  "input_video_id": 5,
  "frame_interval": 10,
  "confidence_threshold": 0.6,
  "model_id": 1
}
```

字段说明：

- `task_name`：任务名称，可选，不传则后端自动生成
- `task_type`：必填，当前支持：
  - `violation_detection`
  - `vehicle_detection`
  - `knife_detection`
- `submitted_by`：必填，建议传当前登录用户名
- `input_video_id`：推荐传，使用上传接口或视频列表接口返回的 `video_id`
- `input_video_path`：兼容旧方式；当不传 `input_video_id` 时，使用上传接口返回的 `stored_path`
- `frame_interval`：必填或使用默认值 `1`，值越大处理越快
- `confidence_threshold`：范围 `(0, 1]`
- `model_id`：可选，不传时优先使用当前激活模型

成功响应示例：

```json
{
  "code": 200,
  "msg": "任务提交成功",
  "data": {
    "task_id": 12,
    "status": "PENDING",
    "task_name": "宿舍楼夜间刀具巡检",
    "task_type": "knife_detection",
    "input_video_id": 5,
    "model_id": 1
  }
}
```

### 4.3 查询单个任务状态

- 方法：`GET`
- 路径：`/api/task/status`
- Query：`id`

示例：

```text
GET /api/task/status?id=12
```

返回重点字段：

- 基础信息：
  - `id`
  - `task_name`
  - `task_type`
  - `submitted_by`
  - `status`
- 输入输出：
  - `input_video_id`
  - `input_video_path`
  - `output_video_path`
  - `result_url`
- 视频元信息：
  - `video_duration`
  - `video_width`
  - `video_height`
  - `video_fps`
- 处理结果结构化字段：
  - `processed_frame_count`
  - `detection_count`
  - `real_inference_executed`
  - `result_video_generated`
  - `used_model_name`
  - `used_model_framework`
  - `video_build_mode`
  - `inference_runtime_message`
- 展示辅助字段：
  - `has_result_video`
  - `detection_summary_ready`
- 其他：
  - `result_summary`
  - `error_message`
  - `created_at`
  - `started_at`
  - `finished_at`

当前版本常见任务状态：

- `PENDING`：任务已入库，等待进入调度阶段
- `QUEUED`：任务已进入队列，等待视频处理线程执行
- `PROCESSING`：任务正在进行视频分析
- `COMPLETED`：任务已完成
- `REJECTED_QUEUE_FULL`：系统繁忙，视频处理队列已满
- `REJECTED_DISK_FULL`：磁盘剩余空间不足，任务未被受理
- `FAILED_INPUT_NOT_FOUND`：输入视频不存在
- `FAILED_OUTPUT_DIR`：结果输出目录创建失败
- `FAILED_METADATA`：读取视频元数据失败
- `FAILED_INFERENCE`：抽帧或推理阶段失败
- `FAILED_ENCODE`：结果视频编码失败
- `FAILED_OUTPUT_COPY`：结果视频回退复制失败
- `FAILED_RUNTIME`：其他运行时异常

## 5. 模型管理模块

### 5.1 上传模型

- 方法：`POST`
- 路径：`/api/model/upload`
- 请求方式：`multipart/form-data`

表单字段：

- `file`：模型文件，必填，当前仅支持 `.onnx`
- `model_name`：模型名称，必填
- `framework`：模型框架，可选，默认 `onnx`
- `uploaded_by`：上传人，可选
- `is_active`：是否立即激活，可选，支持 `true/false`、`1/0`

前端 `FormData` 示例：

```javascript
const formData = new FormData();
formData.append("file", fileInput.files[0]);
formData.append("model_name", "yolov8n_custom");
formData.append("framework", "onnx");
formData.append("uploaded_by", "chenwanyao");
formData.append("is_active", "true");
```

成功响应示例：

```json
{
  "code": 200,
  "msg": "模型上传成功",
  "data": {
    "id": 3,
    "model_name": "yolov8n_custom",
    "file_path": "/home/chenwanyao/graduation_project/storage/models/1778561000123_yolov8n_custom.onnx",
    "framework": "onnx",
    "is_active": true,
    "uploaded_by": "chenwanyao",
    "uploaded_at": "2026-05-13 19:30:00",
    "updated_at": "2026-05-13 19:30:00",
    "stored_filename": "1778561000123_yolov8n_custom.onnx"
  }
}
```

说明：

- 上传成功后，模型文件会自动保存到 `storage/models`
- 后端会对 `.onnx` 文件做一次基础加载校验
- 如果 `is_active=true`，会在上传成功后直接设为当前激活模型
- 为兼容旧调用，`/api/model/add` 当前仍映射到同一上传逻辑，但前端建议统一改用 `/api/model/upload`

## 6. 系统监控与概览模块

### 6.1 心跳上报

- 方法：`POST`
- 路径：`/api/system/heartbeat`
- 请求头：`Content-Type: application/json`

用途：

- 前端定时上报用户在线状态
- 供 `/api/system/status` 中的 `current_clients`、`peak_clients` 统计使用

请求体示例：

```json
{
  "username": "chenwanyao"
}
```

成功响应示例：

```json
{
  "code": 200,
  "msg": "heartbeat ok"
}
```

前端建议每 `20-30` 秒调用一次。

### 6.2 获取系统状态

- 方法：`GET`
- 路径：`/api/system/status`

用途：

- 更偏运行时状态与监控聚合
- 适合展示“当前负载”“并发承载情况”“推理吞吐与时延”

主要字段：

- `snapshot_time`
- `connection`
- `thread_pool`
- `task_queue`
- `inference`
- `system`

`connection` 字段：

- `current_clients`：并发连接客户端数，基于心跳在线表统计
- `peak_clients`：并发连接峰值
- `current_active_connections`：当前 TCP 活跃连接数
- `peak_active_connections`：历史峰值 TCP 活跃连接数

`thread_pool` 字段：

- `core_threads`
- `max_threads`
- `live_threads`
- `busy_threads`
- `idle_threads`

## 8. 推荐联调流程示例

### 8.1 用户管理模块联调流程

1. 添加用户

```text
POST /api/user/add
```

2. 用户登录

```text
POST /api/user/login
```

3. 获取用户信息

```text
GET /api/user/info?username=xxx
```

4. 修改用户信息

```text
POST /api/user/update
```

### 8.2 模型管理模块联调流程

1. 新增模型

```text
POST /api/model/upload
```

2. 获取模型列表

```text
GET /api/model/list
```

3. 获取当前激活模型

```text
GET /api/model/current
```

4. 切换模型

```text
POST /api/model/switch
```

### 8.3 视频分析模块联调流程

1. 上传视频

```text
POST /api/video/upload
```

2. 提交任务

```text
POST /api/task/submit
```

3. 轮询任务状态

```text
GET /api/task/status?id=任务ID
```

4. 获取任务列表

```text
GET /api/task/list?limit=10
```

5. 获取任务统计

```text
GET /api/task/stats
```

6. 播放结果视频

```text
GET /api/video/result?task_id=任务ID
```

### 8.4 系统监控模块联调流程

1. 获取系统状态

```text
GET /api/system/status
```

### 8.5 四模块完整联调流程

1. 用户登录，拿到当前用户名
2. 查询当前模型或先切换到目标模型
3. 上传视频文件
4. 提交分析任务
5. 查询任务状态与任务列表
6. 播放结果视频
7. 查看任务统计和系统状态

## 9. 联调注意事项

- `POST /api/video/upload` 推荐使用 `multipart/form-data`
- `POST /api/task/submit` 使用 JSON，不直接上传文件
- `input_video_path` 使用上传接口返回的 `stored_path`
- 结果视频接口返回的是二进制流，不是 JSON
- 如果任务处理时间较长，前端应采用轮询方式查询任务状态
- `result_summary` 主要给人看；前端优先使用结构化字段，不要依赖解析中文摘要
